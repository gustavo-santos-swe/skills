# ASD-STE100 (Simplified Technical English)

House prose standard for Goose durable text and skill bodies. Based on **ASD-STE100 Issue 8** (April 2021). Full spec: [asd-ste100.org](https://www.asd-ste100.org/).

We do not paste the STE dictionary here. Use approved general words when you can. Use [technical names](./technical-names.md) for domain terms. When a word is unapproved in STE, pick the STE alternative or a technical name.

## Sentence length

| Text type | Max words | Examples in Goose |
|-----------|-----------|-------------------|
| **Procedure** (steps, instructions) | 20 | Skill steps, commit/PR checklists, runbooks |
| **Description** (rules, context, notes) | 25 | Defaults, guardrails, reference sections |

One topic per sentence. Split long sentences. Do not use contractions.

Vary sentence length below the caps. Uniform sentence length reads as machine output. Mix short and long sentences.

## Voice and tense

- **Procedures:** active voice only. Imperative (command) form: "Load the skill", not "The skill should be loaded".
- **Descriptions:** active voice when possible. Passive only when the actor is unknown or irrelevant.
- **Tenses:** simple present, simple past, imperative, future (`will`). Do not use present perfect (`has loaded`) or complex modals unless STE allows (`can`, `must`, `will`).
- **Requirements:** use **must** (not "shall" or "should" for hard rules).

## Words

1. Prefer STE-approved general words (short, one meaning). See [vocabulary.md](./vocabulary.md) for common AI-filler → simple word swaps that align with STE.
2. Use [technical names](./technical-names.md) for software/domain terms not in the STE dictionary.
3. Use one technical name for one item. Do not swap synonyms mid-text (`PR` and `pull request` for the same thing — pick one).
4. Do not use slang or jargon outside the technical-names list.
5. American English spelling (`color`, `organize`, `behavior`).
6. Use articles (`a`, `an`, `the`) and demonstratives (`this`, `these`) before nouns when applicable.

## Structure

- **Noun clusters:** max three words (`user account settings` → split or hyphenate).
- **Verbs for actions:** use a verb, not a noun phrase (`Do the installation` → `Install`).
- **`-ing` forms:** ban as AI-style participial fluff tacked on for fake depth (`highlighting`, `fostering`, `showcasing`; see [patterns.md §3](./patterns.md)). Ordinary software `-ing` terms that name a state, feature, or process stay: `loading`, `caching`, `routing`, `testing`, `pending` (see [technical-names.md](./technical-names.md)). Not as a bare gerund replacing a real verb (`the installation is ongoing` → `installation is running`).
- **Lists:** use vertical lists for complex text (STE Rule 4.3). One instruction per numbered step unless actions occur at the same time.
- **Connecting words:** use `and`, `but`, `because`, `then`, `if` to link related sentences.

## Procedure shape (skill steps)

1. Start with the command verb.
2. If a condition precedes the command, put a comma before the command: `When the test fails, stop the build.`
3. Notes give information only. Notes do not give instructions.

## Descriptive shape (rules, defaults)

1. State one fact or rule per sentence.
2. Put the main point first (compatible with [density.md](./density.md) surface rules).
3. Max 25 words per sentence.

## Mixed shape (PR, ticket, plan, ADR)

These documents combine both shapes by section, not by document:

1. **Briefing, References, Notes, and any rule/context paragraph** use Descriptive shape (≤25 words/sentence).
2. **Changes, checklists, and runbook steps** use Procedure shape (≤20 words/step, imperative).
3. Pick the shape per section. Do not force a whole PR/ticket/plan into one shape.

## What STE does not cover

STE does not target AI writing tells, chat preamble, or review-comment tone. After an STE pass, run [patterns.md](./patterns.md) + [phrases-and-structures.md](./phrases-and-structures.md) for those.

## Quick audit

- [ ] Procedure sentences ≤ 20 words; description sentences ≤ 25 words
- [ ] Sentence lengths vary (not all sentences near the same length)
- [ ] Active voice in steps; imperative commands
- [ ] One topic per sentence
- [ ] Noun clusters ≤ 3 words
- [ ] Articles present where needed
- [ ] No AI-style `-ing` fluff (see Structure above); software `-ing` nouns ok per technical-names
- [ ] One name per referent (no synonym drift)
- [ ] American spelling
- [ ] Requirements use **must**
